# 航空新批通过后的独立只读审计

本轮审计只读航空生产代码，不改已绿的library。验收基线是`fourth-core.log`中的AAM12与精确靶场Bomb7，通过不等于航空全章完成。第4章20、空战8与航空鱼雷3项保留各自日志。以下缺口独立于已经接入的R-048本机探测与R-049战损投影修复。

正常释放路径没有发现双扣：AAM与空投鱼雷由`weapons::launch`每个成功实体调用一次`ordnance_released`，各来源`fire_at`只在其层扣实际ammo；Mk82不创建导弹实体，`surface_attack`一次扣rounds并一次减外挂。`Jettison`只减已声明剩余外挂及ammo，不生成攻击。质量只来自精确挂重与显式装配，未知、内外混挂和油箱投弃仍阻断；完整World保存源质量账。低层spawn的失败原子性是一般基础设施问题，当前正常AAM所有spawn前置条件在弹包内不变，没有证据表明该批会发生部分spawn后回滚质量的实际失配。

最重要的实存缺口及下一最小子包：

1. **受控靶场仍有物性许可探针。** `aircombat2026::surface_attack`在扣弹前读真实平台size来源与地面horizontal armor；己方只需类别已知，aimpoint只声明固定坐标。未识别的受保护设施会因为真实装甲得到不同拒绝回执，缺来源型号亦会在许可阶段暴露支持差异。下一包应给有来源想定目标物性增加明确的己方可知声明，或把未知真实物性的裁决留在Referee pending；不能用真实装甲决定未授权Side的动作许可。一般接触轰炸仍未完成。
2. **新构型仍缺已核接收燃油率alias。** `us_f18e_mk82`的飞行、舰面、雷达、目标AAM资料已经独立v4化，但`offload_factor`对F18 buddy→接收方查`offload_fuel_rates[receiver]`；该新同型构型没有key，会明确拒绝。同一F18已核5.2来源行可支持一个小型v4别名补丁及真实加油回归，不能把此缺口写成全部加油已完成。
3. **声明瞄准点缺己方可见的发现接口。** 生产动作必须知道合法aimpoint key，但当前`own_view`只输出本机燃油/载荷/冷却等，没有公布允许本方使用的来源点和NoAA条件。想定作者可以手工提供，普通AI观察不能自行发现合法参数。应先定义每个点的Side可见性，再输出本方可知的声明；不能直接公开全部全局配置。
4. **航空反潜挂重仍未接完整源装配。** 9.7三项验的是来源投放/时钟/互扰，使用明确mass-neutral想定夹具。`store_weight`仅支持已核AAM与Mk82，尚无Mk54挂重，因此不能把真实弹库数自动当作已核反潜挂载质量。必须继续核对应航空附件的挂重/装配，不猜鱼雷总重或战斗部重。

R-048的新可见字段只报告本机使用的传感器。原始靶场概率、骰组、目标真位置、尺寸、装甲及pending裁决均Referee；相同己方情况、不同隐藏目标位置的命令/投放回执相同，已入七项边界测试。一般战果与精确HP是独立R-049，不能以靶场raw trace收口替代整个观察层审计。

下一航空反潜可读来源是9.7.2转引8.5.4.4：English PDF101/8-21规定航空深弹按分散船阵处理、通常给三个候选深度带、4代主动吊放声纳例外；1代/2代自导深弹基础乘数3/10，任意代声学对抗令其命中率减半，一次最多8枚，传统/自导与两个苏制ASW集束系统分开。仍需回看原页图和附件精确武器行、深度披露来源、major/minor与耐压壳判定，才可打通真实消费。当前没有据此启用新武器或猜值。
