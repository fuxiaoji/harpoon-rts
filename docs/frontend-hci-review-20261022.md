## 2. 当前实际能力与玩家心智模型

当前已有不少自动程序，问题在于它们分处不同层，而且界面没有把权限与持续时间放在一起解释。

| 玩家意图 | 已有能力 | 当前前端入口与缺口 |
| --- | --- | --- |
| 让一艘船沿路线航行 | `Goto`、`SetSpeed`、`SetCourse` | 地图空白点击直接追加航点，或逐项输入X/Y、航速、航向。尚无多选批令。 |
| 多艘船保持相对队位 | 后端已有 `Follow`、`ClearStation`（commands.rs:21–29） | 当前前端未提供设置领舰/队位/解除跟随的专门入口。“编队列表”实际是平铺的单选单位按钮。 |
| 维持一次巡逻或搜索 | 已有5类 `AirMission`，可 `RetaskAircraft`、单机返航、宿主召回 | 甲板按钮能发CAP/ASW/侦察/突击；当前任务列表按任务类型与机型汇总，不是可编辑任务对象。 |
| 让程序自动挑敌并开火 | `SetWeaponsFree` | 已有“自动选敌开火”；指定目标的持续交战独立存在，关闭选敌不取消目标指派。现有解释应保留。 |
| 只让程序继续攻击指定接触 | `AssignTarget`、`ClearTarget` | 已有目标卡与在飞弹药/BDA；不是整席AI托管，也不是一次射击。 |

| 让LLM提供建议或执行 | 独立参谋的 advise/execute、自动推进 | 与FSM并列；按钮与状态不构成统一权限模型。 |

## 4. 最小交付包与实施顺序

第一批应交付可立刻减少操作的完整闭环，不等全部高层任务系统完成：

1. **统一中文显示与明确地图模式**：补显示名函数、中文主标签和原名/ID详情；默认浏览，航路草稿确认后提交。读取、选择和移动海图不发游戏命令。
2. **选择编组与群体机动**：列表复选、多选数量、组名、保存编组、定位编组；批量设置航速/停止，按每舰当前位置预览航路。既有Follow关系明确展示，不能让Goto悄悄与跟随/航空任务争夺导航。对混编选区显示适用数量与跳过原因。
3. **可信人工接管**：先保证整席托管可关闭，并实现服务端单舰人工锁定。前端显示“人工控制，自动辅助暂停；恢复辅助”。补队列与既有计划取消/保留规则，保证下一FSM窗和迟到LLM结果不覆盖。
4. **桌面和平板视窗结构**：编组优先，选择与命令托盘常驻；平板抽屉内部滚动。关闭未配置AI参谋的大面积空面板，保留一个可发现的打开入口。
5. **看得懂的命令结果**：组命令显示“8艘已排队；2艘不适用”，然后按真实回执更新；定位拒绝舰并给可行动原因。暂停时显示“模拟暂停，尚未执行”。

本批通过后才称“多舰基础指挥完成”。基于任务模板的自动分配、逐域托管和统一警报管理是下一批，不能以一个总开关或展示统计替代。

### 群体导航的现有后端边界

- `Goto`设置waypoints而未清除station（sim.rs:129–148）；`Stop`会清除station和waypoints（149–156），但它的语义是立即停止。不要为改航路偷偷先发Stop，因为那会产生额外运动结果。
- `Follow`/`ClearStation`已经可复用；编队机动应主要移动领舰，让跟随成员继续维持队位。自由编组批量Goto需要说明是“各舰驶向目的地”，并提供相对偏移，避免所有舰追同一点。
- 航空 `Goto/SetCourse`不会自动替换CAP/ASW任务（commands.rs:37–39已明确）；界面需使用明确的RetaskAircraft/manual意图。潜艇深度、飞机高度、固定设施分别处理。
- 目前逐条 `/api/command`没有事务与统一执行回执。首批可以顺序批发并诚实展示部分失败；声称原子队形调整或整组同时生效前，需要服务端批命令接口、校验和录制支持。

## 5. 自动辅助与人工覆盖的权限设计

### 建议玩家可见层级

| 模式 | 玩家理解 | 当前实现基础 | 新增要求 |
| --- | --- | --- | --- |
| 人工控制 | 我下令，已下的航路/巡逻与系统自卫继续 | 现有普通命令与底层任务 | 明确显示当前持续命令，不能把“AI关闭”解释为一切自动行为停止。 |
| 任务辅助 | 我给目标与范围，程序维持这个任务；我可改细节 | AirMission、Follow、交战政策、共享维护部分可复用 | 任务ID/归属/允许域/完成或撤收条件；不获得全席自由改派权。 |
| 只提建议 | 显示建议，批准才改变任务 | LLM advise已有 | 按当前观察/权限版本重新校验；逐项解释影响，不展示未拥有能力的按钮。 |
| 全席托管 | 程序可安排未被人工锁定的兵力 | FSM、LLM execute已有粗粒度入口 | 全自动命令源共用权限；单舰/编组例外可见，允许显式恢复。 |

常用界面只出现玩家概念。需要了解实现时再显示“内建程序，无需模型密钥”或“LLM参谋，需要模型服务”。自动推进时钟是独立设置，不能隐含在控制授权内。

### 服务端必须补的约束

1. **权威控制状态**：至少保存 `unit_id → controller/manual_lock`；进一步按 navigation、sensors、engagement、air_operations、damage_control分域。显示状态来自本方观察，不能只保存在浏览器。
2. **先校验、后转移**：当前command_handler在命令实际执行前释放租约（main.rs:484），而API只负责排队。无效/拒绝命令不得顺带解除旧任务；接管与合法人工命令应作为一次可审计的状态转移，失败给出原因。
3. **所有自动来源共同检查**：FSM输出、想定doctrine、共享Supervisor维护、定时发射、LLM计划应用和迟到建议都检查同一权限版本。只过滤FSM不足以阻止旧计划或其他来源重发。训练控制与其课程权限单独保留。
4. **接管撤销准确**：接管导航时取消该单位待执行AI导航/相关维护，不擅自清空自卫；接管交战时说明已有在飞弹药无法撤回。已有Follow和AirMission是否保留必须显示，不依靠玩家记住隐藏优先级。
5. **默认不悄悄到期**：人工锁定默认持续至玩家点“恢复辅助”；如允许定时恢复，需明确倒计时与可取消入口。与AI任务600秒复核租约分开，不能复用同一个字段。
6. **版本与并发**：人工操作提升authority revision，旧观察生成的LLM建议及异步队列不获得新权限；保存/恢复保留锁定，换阵营/新局不复用旧EntityId控制状态。
7. **恢复是新决策**：显式恢复辅助后从当前本方观察重排，不重放锁定前旧命令。回执记录来源、单位、权限版本、实际执行/拒绝与原因。

可以先以“整单位人工锁定”实现可靠最小版，再细分域。第一版不要展示未实现的五个独立授权开关。展示“继续辅助”之前必须明确它会允许程序改变哪些内容。

### 中文显示与稳定ID分离

建议使用单独、可审计的presentation目录：按platform/weapon/sensor稳定ID记录 `zh_name`、`short_name`、`original_name`、`aliases`和翻译备注。单位实体ID、class、weapon与传感器ID保持原值；存档、命令与规则索引都不从中文名反向猜ID。

- **单位名与级名分开**：`#3`可以显示“055型驱逐舰A”，级名“055型驱逐舰”；不要凭型号虚构真实舰名。`CV-16 LIAONING`可显示“辽宁号（16）”。
- **机型与任务分开**：“歼-15 · 空中巡逻1”，不把`CAP`词典展开后得到“蓝方 战斗空中巡逻-1”当作完整自然名称；AEW译“预警机/预警直升机”时以已知机型为准。
- **武器简名与型号都留**：如“鹰击-18反舰导弹（YJ-18）”“Mk 48鱼雷”“标准-2防空导弹（SM-2）”。不同变体按真实ID单独映射，不把所有Harpoon/SM系列合并；未核实的专名使用可理解类别加原型号。
- **未识别敌接触守信息边界**：“水面接触 C17”，不能由隐藏真态补成中文具体级名。只有本方已识别 `class_name`才翻译；C编号与单位#编号不得互换。
- **原文可追溯**：详情展示原名/稳定ID，提供复制；允许按中文、拼音/英文别名、型号与ID搜索。未知名称回退原文并标记待译，不静默漏掉单位。
- **所有出口统一调用**：友军/接触列表、地图绘制和文字测量、单位卡、武器菜单、甲板、任务行、toast、战报/复盘都调用同一展示层；避免DOM翻译和canvas产生两套名字。
- **操作自然中文**：“保持编队”“空中巡逻”“只提建议”“恢复辅助”“下达航路”“已排队，待模拟推进”。`TTL`称“复核期限”；`BDA`首次解释为“确认估损”；`FMP`首次为“军用推力（不加力）”，具体支持性仍以现有游戏接口为准。
