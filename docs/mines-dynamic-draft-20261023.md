# 动态布雷与逐雷猎雷来源草案（2026-10-23）

**仅来源与设计草案，尚未实现、没有新红/绿测。** 本阶段为保护正在验收的包，不修改已注册 `mines2026.rs`、`data/rules/mines-2026.json` 或既有测试。原常规雷场/扫具11例及特殊类型拒绝门继续保留；初始雷场和已有纯API不等于动态布雷/猎雷已执行。

证据目录：根 `artifacts/rules-following-20261023/mines-draft/`。已先检索三本中文核心RAG，视觉复核英文2026-01-01 PDF122–126/印13-1至13-5全章五页、关联主动声纳门PDF52/印5-13、中文PDF124及中国海军2025-12-01 AnnexG PDF78/G-1。`manifest.json` 保存原件SHA、视觉页和冻结三文件哈希/11个测试名；所有原件只读。`mechanisms-draft.json`、`annex-variant-candidates.json`、`proposed-contract.json`、`red-cases.json` 与 `implementation-packages.md` 分别记录源机制、确切变体、接口、27项未执行测试设计和实施分包。

已核最小规则：有明确携雷能力/数量的水面舰船最大20节、海况≤4；15节只是常用速度。潜航潜艇约5节、海况≤5，浮航不能套海况5例外。布雷舰/专用雷轨/其他具能力舰船/改装商船每180秒分别20/16/8/12枚，交战的水面舰船速率减半。每枚雷的投放方法、锚深/雷壳深度、真实海床与雷排间距都必须有据；“现代舰”“某国舰”不是装备依据。

潜艇每个实际可用鱼雷管可发一雷，英文PDF125明确每管装填两个战术回合，即360秒。中文PDF124视觉写每两个战术回合两具管；本项目仍按英文权威版，不与第10章鱼雷装填计时混用。Shallow雷壳布设后360秒待发，IntI为540秒；P/S与其他深度没有通用数值，不补猜。延时/船计数器须明确装配和设置。

空投不是整齐规则排：实际参与飞机数除以2是一次过场的攻击次数，间距D6×100码。奇数飞机无取整规则，位置足迹/部分过场的实时检查时点也未给通用数值。航空投雷的机型挂载、确切质量与投放高度/速度须有单独来源，不能借炸弹参数。已视觉核实的例子包括Chen-1 500总质量495kg、Chen-0 500为500kg；同族1000变体的重量/投放方法/DP不同，不能按名称合并。

猎雷须先搜索、再分类为雷、再逐枚中和。英文PDF126明确每枚 `D6/2小时`，即保存一次D6后用1800–10800秒工作，且不能在战斗环境中执行。通用主动声纳发现不自动完成矿型分类；避雷/特调舰壳声纳只适用离底系留雷，沉底雷需要专用猎雷声纳。ROV/潜水员/海兽的工作范围、深度、器材和耗材必须有具体来源/想定说明。

推荐顺序：先明确库存与真实布雷作业状态，再分开接水面规则雷排、潜艇物理管和空投随机雷场；逐雷中和可先从本方已合法分类的已知单雷接触执行，完整搜索/分类随后单独接入。已有Command::Mines可扩展Action；服务器验证、航空真实质量扣减、潜艇物理管锁与传感器目标投影由主代理协调共享入口。

必须先解决的衔接：现有Field只存规则排抽象，没有逐雷剩余数。正在布设/部分已武装的半排、或猎掉其中一枚后，不能凭空沿用完整排命中率、乘以1−1/N、画一个清除圆，或套扫雷最低25%威胁。首个可审范围可以是有明确相位适配的完整雷排批次、带激活延时的完成后启用雷排，及完整已知雷体清单的逐雷中和/全清后退役；部分雷场的自动袭击仍需独立来源程序。不能让一个待裁状态在实际对局中成为强制清空雷场的漏洞。
