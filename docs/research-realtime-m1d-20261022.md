# M1d：密集任务更新、事件重新触发与公开过期过滤

日期：2026-10-22。范围：本项目导航诊断与真实LLM持续时钟验收。**已完成40局脚本检查及2局真实模型闭环；不是新算法、一般胜率、推理预算联合方法或CCF A论文成果的验收。**

本轮发现并修正的是评测基础设施缺陷：任务不匹配条件持续为真时，第二次任务变化没有新的布尔边沿；第一次调用的旧回复被拒收后，纯事件控制器可能一直休眠。另为所有方法提供同一公开过期过滤。原M1c数据及其922文件归档保持原样，不能把新机制回填给旧实验。

## 场景、共享语义与冻结条件

D5最小压力例沿用D1初态与首事件生成器，在第一次任务更新后30模拟秒再替换一次目标；第二目标相对第一目标东移0.15海里、南北镜像，期限为第二次发布后900秒。每30秒还有一次普通重复通知，共39次，不改变任务revision。只计最后仍有效任务的到点完成；被替换任务不再是当前目标。这是双变化仪器检查，不是完整任务族、传感器噪声或交战场景。

私有裁判只在事件发生时发布当前任务，未来事件时刻、目标和种子不进入控制器/模型。新增当前公开通知计数及DSL字段`notice_seq`。人工与模型条件共用执行器、一个在途请求、锁存与拒收规则。

- 旧模式：条件假到真时触发，安装时已经为真也触发一次。
- `--revision-keyed`：保留以上规则，条件持续为真但公开任务revision改变时也触发。普通通知不改变revision，因此不会重新触发本轮使用的任务不匹配条件。新事件可在请求期间锁存，旧回复仍然拒收并计成本。
- `--skip-expired`：当前公开截止之后清除锁存触发，不再发起过期任务调用；已经在途的请求不取消、不删账。丢弃触发数不同于节省调用数，终局时本来就不能再发请求。

每批在调用前保存协议、顺序和101文件源码快照。三批34份生产核心源码完全一致，沿用M1b冻结导航核心；本轮没有修改当前生产裁决、玩家服务或历史战局。具体接口见[协议](../research/realtime/live-protocol.md)。

EM的初始化在T0调用、T73生效；模型三次输出的条件均为`task_mismatch == 1`。第一次任务更新的请求在T165发出，等待期间T195的第二次变化被锁存，旧回复在T238拒收，随后立即用当前观察再次调用。EH对应过程是T237拒收并接续。39次普通通知没有为这条条件增加调用。

本轮5份真实回执均为合法结构化输出，累计input/output为53565/395；提供方reported reasoning/cached input均为0，金额缺失保持null。失效的两份回复全部计入，不能只保留最终成功请求。9.98–14.47秒是客户端记录的端到端调用时长，不是隔离出的纯模型推理时间；请求档位与可报告reasoning用量分别记录。

这个例子中模型条件与人工条件相同，EM还承担一次初始化。两局的到点差异同时受服务时长等因素影响，**不能推出模型自写条件通常更差、人工事件通常更好，或两者等效**。导航动作本身只是前往公开目标，不能据此证明LLM的必要性。
