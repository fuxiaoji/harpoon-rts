# 本机来源扫描与火控几何（2026-10-23，来源子集已验）

仅显式 `hv2026-rts-v4`。这项修复分两步，不能把传感器确实收到信号等同于已经测得目标运动。

第一步已有 `fourth-core.log` 证据：真实扫描不再只记录融合后的最佳接收器，而逐个保存成功的 `(observer,sensor,target)` 时钟。探测56例、夜战AAM12例通过；共享接触、损坏或失败接收器不能产生本机成功记录。夜间AAM的本机雷达/IRST条件使用独立的逐秒新鲜度政策，不要求180秒运动观测。

第二步来源红证据在 `artifacts/rules-next-20261023/validation/fcs-own-motion-red.log`：本机仅IRST方位轨迹连续181个实际tick，友舰目视测距使一方融合图已知航速，旧 `world_solution` 错误放行；友舰观察180秒后本机才取得第一份测距样本，旧解算也错误借用该运动时钟。两例均为实际 `sim::tick`、来源扫描和生产解算，没有用 `record_own_contact` 夹具制造轨迹。修复后 `artifacts/rules-next-20261023/validation/fifth-core.log` 探测61例全绿；同次AAM12、AAW25、航空ASW3、source_review3、Bomb7均绿。该日志另有鱼雷目标失败，不宣称本批全工作区验收。

来源：中文三本核心RAG检索“火控 雷达 诱饵”“Distraction Decoy”“雷达 航向 航速 一个战术回合”，回看英文2026-01-01 §5.2.3（PDF41/印5-2）和§6.3/6.3.3（PDF70、73/印6-2、6-5）。PDF41新视觉在 `artifacts/rules-all-20261023/detection/own-motion-p041.png`。来源区分单平台解算与有明确数据链的交叉定位；本包不默认为所有友舰共享火控数据。

实际执行：`detection2026::project_report` 对每个成功接收器复用原有 `5.bearing` 保存骰及来源误差，生成该接收器的报告。融合图标直接使用同一报告；Gen5 AIR的测距仍保留±3度方位误差。本机报告包含观察者位置、报告方位、实际测距资格对应的报告位置、当时接收器类型/来源配置。仅方位接收器的 `measured_position=None`，1海里图标锚点从不成为测距。没有读取目标真航向或真航速。

`firecontrol2026::Track` 的 `report`、`motion` 都是可缺省且空值省略的字段；旧字段形状可恢复，缺证据不会补造。`record_detection` 按同一个观察者/接收器的实际测距位置形成自己的运动估计；`world_solution` 仅用该报告的位置、该接收器的运动与规避证据。融合图只用于确认本方接触仍存在；改动融合位置/航速或清空side级运动表不应影响已成立的本机解算。

RTS政策单独记在 `data/rules/firecontrol-2026.json.execution_revision` 并参与v4指纹：连续逐秒测距180秒后，用自己的报告位置差求近似航速与航向；样本间隔超过1秒重建该局部运动时钟，报告只接受当前/前一tick。静止目标给已知零速，不捏造目标朝向。四战术回合的来源接触丢失时限仍保留在Track接触历史中；此处更严格的几何新鲜度是当前缺少完整预测/定位程序时的明确RTS限制，不把它冒称原文要求每秒观察。

已验证案例：两条来源红、实际本机180秒门前后、T90完整World保存恢复、改变融合字段不改变本机解算、损坏/修复后只重建自己的时钟、旧Track默认/省略字段兼容、既有Gen5 AIR公开点与本机报告误差完全相同。探测目标61例已全部通过；执行次数不是独立规则数，也不是整章完成率。航空两个既有Track夹具仅按所有者授权补 `report:None,motion:None`，原场景质量与时钟不变。
