# M1d之后的工作包：先完善M2，保留M3有效性门

2026-10-22进度：M2a已完成有界初始化恢复、固定/事件与Public基线、8条件预实验和归因控制，见[报告](../../docs/research-realtime-m2a-20261022.md)。下文保留原工作包规格；完整M2、七臂真实/多种子、单元方差与正式样本量仍未验收。后续优先控制初始化、重试上限和目标几何，扩相位/重复采样，再用有推理质量差异的任务进入M3；不将本轮IR1或耦合几何结果当作最终排名。

这是待执行方案，不是已经取得的结果。M1d报告和各批冻结协议记录已完成范围；此处不能用于给总计划勾完成。

当前导航任务的动作仅为hold/前往公开目标，本身无需LLM。M1d的旧布尔边沿故障和公开过期过滤应成为所有方法共享的基础设施，不能包装为LLM调度算法创新。单次真实EH/EM比较也不能确定最优唤醒方式。

## 1. 先补可靠性和强基线

- 用明确失败案例检查初始化调用跨越任务更新、条件尚未安装时的恢复；确定有限重试/超时语义，所有调用计额度，纯事件和定时兜底分开报告。不得为模型条件组隐式添加免费的人工任务监听器。
- 为每个方案保留任务版本、公开截止、在途请求和执行回执的共同校验。新条件的执行表达力、监视频率、锁存、重新触发及冷却对人工和模型一致。
- 加入无需LLM、只读同一公开输入的目标跟随控制，实测其运行耗时。其用途是检查任务/执行器与说明LLM的必要性边界，不能将其称为军事实战指挥能力。
- 同时报告原始固定网格、带共同公开失效检查的固定网格和强人工事件/混合基线。若增加“现有计划可证明仍有效则不调用”的廉价门，必须把原理、适用任务和对所有方案的影响写清，不能只优化研究方法。

## 2. 把任务节奏与响应窗口分开操纵

最小D5只用30秒变化间隔和900秒期限来复现漏触发，不能代表密集事件分布。下一生成器将第二次任务间隔、期限、首事件相位和重复通知频率分别作为显式参数；目标生成与算法胜负无关，不根据试跑排名筛场景。

先以保存的请求耗时范围作脚本延迟校准，再冻结少量“变化间隔短于/长于响应时长”和“宽松/紧迫”组合。固定60/300/600秒网格均为T0起算，开发时覆盖其相位，模型不见未来事件。及时脚本必须可行；若连及时控制也无法完成，先修正任务或标记物理不可行，不能作为模型推理失败。

这批需要回答的是：立即响应的时效收益，何时被随后任务替换导致的无效调用抵消？固定网格何时因错过机会而失败，何时可以把相近变化合并成一次有效决策？不要求事件方法必胜。

## 3. 再做同模型唤醒探索

固定low档和一个在途请求，比较七种已实现方式；按多个预先冻结的调用上限展示效果与实际token用量，初始化/失败/过期/被替换的请求全部入账。调用上限不等于金额或token严格匹配；金额缺失保持null，不用调用数伪装实际费用。

场景/相位配对，运行顺序按服务时间块交错。完整对局作为统计单位，不能用一局内的多次调用充当多个独立样本。先用开发批估计对局差异与服务延迟，再选择最小关注效应、正式样本量和留出结构；不从M1d四个脚本种子推断真实模型方差。

## 4. 与M3相接，而不是跳过难度验证

M1b四个固定快照三档均达到有限最优，目前没有“多想改善质量”的证据。后续要先构造带实际任务冲突、后续约束或公开观测不确定性的分配任务族；同时保留公开输入规划器及其实际计算成本。增加船/任务数量必须体现实际组合决策，不能只加无关文本。

先在暂停/零延迟诊断分支测计划质量，再在持续时钟中测迟到损失；两者分别报告。只有出现跨开发实例可重复的质量/时长差异，才扩大低/中/高以及按观察选择预算的闭环研究。若传统方法明显占优或质量继续饱和，如实解释适用边界，并继续调整科学问题，不将简单联合argmax改名为理论创新。
