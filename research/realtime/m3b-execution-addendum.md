# M3b 执行补充协议（模型请求前冻结）

2026-10-22。补充 m3b-protocol.md，不追改 M3a 或早期模型数据。本文的修改来自客户端能力核对和机制实现；形成时尚未发送 M3b 模型请求。

- 采用既有 M3a-v5 冻结导航核心，覆盖最小 JSON 服务与研究任务层；生产引擎和玩家服务不参与本批。导航是 Harpoon RTS 连续运动改编；任务服务、作业包与收益是研究假设。
- R1 每任务连续在 0.12 海里圈内服务 30 秒，收益为 1。进入服务先请求停止，实际减速仍推进；漂出圈时服务计时清零，由共同执行器返航。截止参照使用同一过程。两事件间隔均小于首任务及时导航服务耗时，因此本批不能识别“第二事件前完成旧任务”的情况。
- R2/R3 的小规模枚举参照与共同检查点接续为暂停的质量参照。保存完整 CPU 时间和候选数；首批不把这部分免费计算宣称为可部署在线策略，也不以其与模型墙钟成绩的差距作部署效率结论。R4 必须把在线决策开销推进世界。
- R3 的模型沿用 gpt-6.1-sol，客户端为当前 codex-cli 0.163.0-alpha.11。低、中、高使用服务端 model_reasoning_effort 配置；单请求超时 180 秒，宿主并发 1，最大 72 次，无失败补样。连续三次请求无有效服务回复则停止后续请求，保留整个已发批次与未知用量，不自动更换后端。
- **输出上限偏离原设计**：官方 API 支持 max_output_tokens，但本次已认证 Codex CLI 未核实等价的可控硬上限；本批明确记录 max_output_tokens=null。三档同短 JSON 输出结构并不能限制内部推理 token。因此先导只能比较实际调用、token、时延与效果，不能声称总输出硬限、严格 token 或金额匹配。正式预算约束实验须先解决接口控制。
- 模型进程使用随机命名的空临时目录，关闭项目文档注入（project_doc_max_bytes=0）及可配置工具；任何工具使用使样本无效。目录名不包含结构、答案或预算档。所有努力档得到完全相同的公开快照和提示；保存用量与简短行动理由，不保存内部推理文本。
- 共同检查点设为快照后 240 秒。模型首次命令仅在延迟严格小于 240 秒时可执行，240 秒及以后按迟到处理，由共同接续器根据当前公开状态行动。此边界在模型请求前固定。
- 模型请求排序在冻结清单中固定：快照按固定种子打乱，每快照六次请求在两轮中用平衡的三档排列。失败计入请求总量；延迟回放、分支、重复请求不计作独立场景。
- 为避免“最优行动”随等待变化但提示目标不明确，R3 首要目标冻结为对 0/60/180 模拟秒等权延迟分布的后验期望累计价值；三档均看到该分布。有限参照在同一分布下选单一首次行动。各共同延迟的前沿、零延迟内容质量和实测时延回放仍分列。失败回复执行 wait 的后果并继续共同接续，不把本可由接续取得的收益强制清零；无效交付率单独报告。
- R1 同样为暂停规划的脚本机制诊断。所有臂固定注入脚本响应时间，Public 及 Q-S 预测器的本地 CPU 单列；本轮结果不证明这些在线计算没有时延成本。

接口核对：[Codex 配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)，[OpenAI 推理模型指南](https://developers.openai.com/api/docs/guides/reasoning)。客户端版本、实际命令与 usage 保存在每次回执中。本文不宣称具体金额或提供方内部实现。
